# 用 Pages CMS 写博客

后台入口：<https://app.pagescms.org/>  
博客地址：<https://witchklee.github.io/>  
仓库：`WitchKlee/WitchKlee.github.io`，分支：`main`。

## 第一次登录

1. 打开后台入口，选择使用 GitHub 登录（Sign in with GitHub）。
2. 按页面提示安装或配置 Pages CMS 的 GitHub App。
3. 在仓库授权范围选择「Only select repositories」，勾选 `WitchKlee.github.io`，完成安装或保存。这里只需要授权博客仓库。
4. 返回 Pages CMS，选择 `WitchKlee` 下的 `WitchKlee.github.io`，再选择 `main` 分支。
5. 页面应出现「文章」「站点信息」「头像与外观」「页面」「友情链接」「高级编辑」和媒体管理入口。仓库已经有 `.pages.yml`，不必再新建或覆盖配置。更新后没看到新菜单时，刷新页面并确认分支是 `main`。

如果没有看到仓库，在 GitHub 的 **Settings → Applications → Installed GitHub Apps** 中找到 Pages CMS，点击 Configure，检查它是否已获授权访问 `WitchKlee.github.io`。授权后返回后台刷新。

## 新建文章

1. 点击「文章」，再点击新建按钮（界面可能显示 New、Create 或 Add）。
2. 填写「标题」；「文章时间」使用北京时间，用于排序。
3. 「分类」填一个名字，例如 `随记`；「标签」每项填一个，可以添加多项。
4. 在「正文」中写作。Editor 是可视化编辑，Source 是 Markdown 源码。
5. 暂时不发布时，保持「发布到网站」关闭，然后点击 Save 保存。
6. 准备公开时，开启「发布到网站」，再点击 Save。

新文章的文件名会自动生成，通常不需要手动填写。文章链接由文件名决定；修改标题不会要求你更改文件名。已有文章尽量不要重命名文件，以免已分享的文章链接改变。

**草稿的含义：** 关闭发布开关后，文章不会出现在博客正文、首页、搜索或 RSS 中。但文件会保存到公开的 GitHub 仓库，能被访问仓库的人读取，因此不适合保存私人内容。

**保存与发布：** 保存会写入 GitHub，并触发「发布博客」工作流；网页要等部署成功才更新，并非点保存后立刻变化。`published: false` 是草稿开关；未来的文章时间不等于定时发布。

## 排版、图片与首页摘要

普通正文可以用工具栏插入标题、加粗、列表、引用、链接和图片。

上传的图片存入 `source/images/`，写入文章的公开地址为 `/images/文件名`，网站构建后可直接访问。上传时文件名会安全化处理，以保存后显示的实际路径为准。

也可以在媒体管理页先上传，再在正文中选择图片。不要删除仍被文章或头像引用的图片。

若希望首页只显示开头，在 **Source** 模式中，在摘要和正文之间单独放一行：

```markdown
这里是首页显示的摘要。

<!-- more -->

## 正文标题

这里开始写完整正文。
```

含 `<!-- more -->`、Hexo `{% ... %}` 标签或自定义 HTML 的文章，建议全程使用 Source 模式保存；可视化编辑器不一定能保留这些特殊标记。两篇现有示例文章都含摘要标记。Markdown 源码模式中的图片可按下面格式插入：

```markdown
![图片说明](/images/photo.jpg)
```

## 修改、撤下文章

在「文章」中找到文章并点击标题，编辑后 Save 即可更新。

临时撤下时，关闭「发布到网站」并保存。这样保留文件，但下一次部署后博客不再显示它。删除则会从仓库当前分支移除文件，因此通常先用撤下更方便。

## 关于我与友情链接

- 「页面 → 关于我」：修改页面标题和正文，保存后自动更新。
- 「友情链接」：每一项是一张友链卡片。填写网站名称、以 `https://` 或 `http://` 开头的完整地址、介绍；头像图片和头像文字可选，图片优先。可以增加或删除条目，再保存。

## 更换头像与网站图标

1. 进入「头像与外观」。
2. 找到「博主头像 → 头像图片」，选择媒体库中的图片，或上传新头像。无需手动填写路径。
3. 根据喜好调整「圆形头像」和「头像悬停旋转」。
4. 点击 Save，等「发布博客」部署完成后查看。

「浏览器与设备图标」中可分别选择小图标、常规图标、苹果主屏幕图标和 Safari 固定标签图标。小图标建议 16×16 PNG，常规图标建议 32×32 PNG；苹果图标建议正方形 PNG；Safari 固定图标使用单色 SVG，留空不启用。更换浏览器图标后可能需要关闭旧标签页再重新打开，浏览器可能缓存图标。

## 更换站名、昵称与简介

进入「站点信息」，修改「网站名称」「网站副标题」「网站简介」「博主昵称」，再保存。这里还提供关键词、联系邮箱、语言、时区、分页、高亮、搜索数据和 RSS 设置。

网址与根路径当前分别是 `https://witchklee.github.io` 和 `/`，与现有 GitHub Pages 部署对应。改动这两个字段不会自动购买或绑定新域名。

## 菜单、侧栏、目录与页脚

这些项目都在「头像与外观」中按小标题分组：

- 「主题布局方案」：Muse、Mist、Pisces、Gemini 四种 NexT 布局。
- 「启用深色模式」：是否跟随访客系统使用深色模式。
- 「导航菜单链接」：修改现有菜单的目标路径及图标。格式为 `/about/ || fa fa-user`；菜单文字可在「高级编辑 → 导航文字与翻译」修改。
- 「导航菜单显示」：显示或隐藏图标、数量标记。
- 「侧栏」：选择位置，以及自动展开、点击展开或完全隐藏。
- 「社交与订阅链接」：修改现有链接。要新增任意平台、删除链接、重排导航或增加新菜单，请用「高级编辑 → 完整主题配置」编辑 `social` 或 `menu` 的条目。例如在 `social` 下添加 `GitHub: https://github.com/WitchKlee || fab fa-github`。
- 「文章目录」：开启目录、编号或长标题换行。
- 「页脚」：建站年份、版权署名、图标、动画、颜色和主题署名。
- 「主题字体」「主题动效」「站内搜索入口」：对应功能开关。当前中文字体、标题样式、字号和间距还受自定义样式控制，需修改「颜色与排版样式」中的对应规则。

## 分类页、标签页、友链页说明

展开「页面」可以编辑这三个页面的标题和开头说明。分类与标签列表由文章的分类、标签自动生成，不需要在页面中手工列出。

「友链页说明」的正文使用 Markdown 源码编辑。保留 `{% friend_links %}`，卡片会在这个位置显示；可在它上方或下方增加说明文字。

## 高级编辑

这里提供完整源文件的编辑入口：站点配置、主题配置、颜色与排版样式、导航翻译、本地新文章模板、友链卡片模板、交互脚本、使用指南，以及原来无扩展名的旧文章原稿。

「颜色与排版样式」中的 `--blog-accent` 是强调色，`--blog-card` 是卡片背景，`--blog-serif` 是中文正文字体；文件中还包含深色模式配色、文章字号、行距、头像尺寸和友链布局。样式格式是 Stylus/CSS。

普通设置优先使用中文表单；高级入口用于增加表单未列出的任意配置，或调整源码样式与逻辑。它们编辑的是同一份文件；保存前刷新到最新版本，避免同时开着旧表单和原始编辑器相互覆盖。

本地新文章模板用于 `npm.cmd run new`；Pages CMS 新文章的字段与默认值来自内置「配置 / Settings」中的 `.pages.yml`。依赖安装和发布工作流仍按项目代码维护。

目前每项配置的覆盖情况见 [Pages CMS 接入覆盖清单](PAGES-CMS-COVERAGE.md)。

## 保存后在哪里查看

打开 <https://github.com/WitchKlee/WitchKlee.github.io/actions>，查看最新的「发布博客」。绿色对勾表示构建和部署通过，再打开博客查看。看到旧内容时按 `Ctrl+F5` 强制刷新。

如果部署红色失败，打开失败的工作流查看详情；也可以把失败链接发给我排查。不要反复重建配置或删除文章。

## 网页编辑后继续在电脑上写

后台修改发生在 GitHub，电脑上的文件不会自动同步。下次在 VS Code 本地编辑前，先进入博客目录执行：

```powershell
git pull --ff-only
```

若本地已有未提交修改，先保留或提交这些修改再同步；遇到冲突不要强制覆盖。以后只在 Pages CMS 写作时，不必运行本地命令。
